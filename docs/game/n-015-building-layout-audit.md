# N-015 五建筑布局冲突审计

日期：2026-08-23  
范围：只读验证 Master Doc 建议 footprint 是否能直接落到现有 10×6 / 10×8 地图；不修改 `WorldCatalog`、碰撞、出生点、NPC 或存档。

## 结论

五栋建筑的六层 PNG 可以继续作为正式资源保留，但**当前不能诚实地直接铺到地图**。Master Doc 的建议 footprint 与现有单格地标/少量阻挡格不是同一合同；若从角落向地图内展开，会新增 48 个阻挡格，并且铜闸工坊、种源棚、巡护亭分别压住出生点或 NPC。

因此 B4 保持 `BLOCKED by topology decision`：先完成不依赖建筑拓扑的 B1–B3；在 Product Owner 另行批准地图布局变更或批准“纯视觉、不承担碰撞”的缩小展示方案前，不从 PNG 猜碰撞，也不让玩家穿过完整建筑。

新增阻挡合计：`16 + 18 + 3 + 3 + 8 = 48`。

## 已锁定、可安全先行的合同

- 六层顺序固定：`base → structure → roof → detail → interaction → state_fx`。
- `base/structure/detail` 不决定碰撞；`roof` 是唯一候选遮挡层；`interaction/state_fx` 不写回存档。
- 运行图保持原生 24 px 网格、nearest、整数缩放；高清建筑图继续只用于展示卡。
- 入口、碰撞与 NPC 站位必须来自后续显式地图合同，不能从透明像素 bbox 推断。
- B1 的地形、静态角色、作物、放置物与紧凑 HUD 可独立推进，不跨越本阻断。

## 后续复闸所需唯一产品选择

1. **地图重排方案**：允许扩展/重排两张地图、出生点、NPC 站位与 blocked cells，再按建议 footprint 放完整建筑；或
2. **纯视觉缩小方案**：建筑压缩为不超过现有 blocked cells 的装饰表现，明确不承载真实 footprint；这会牺牲建筑比例和入口可信度。

在选择发生前，B4 不实现，N-015 仍为 `active / PENDING`。

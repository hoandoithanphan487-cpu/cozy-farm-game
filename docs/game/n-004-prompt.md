## 1. 任务一句话

在现有 Swift + SpriteKit 工程（`macos/CreekSprout/`）中实现**数据驱动的轻量加工站**：放置一个加工站放置物，把收获的中高单价作物加工成更高价值成品，成品可投入出售箱结算——「种植→加工→售卖」第三去向；加工即时完成、失败不扣料、成品定价 +30%~+40%、不破坏 PRD 6.8.1 与 174/894 教学节奏。

## 2. 输入基线（以现有源码为准，不得编造数值）

- 经济基线（PRD 6.8.3，已由 `EconomyCatalog.swift` 实现，**不得修改**）：雾萝卜 28/2天/58、溪叶菜 46/4天/92、琥珀豆 62/6天/48、铃花莓 78/7天/2×44、蜜穗瓜 96/8天/205；体力 100/天、农耕动作 2 点/次。
- N-002 经济模拟结论（`docs/game/n-002-economy-report.md`）：加工加价 +20%/+40% 均不破坏 6.8.1；**雾萝卜加工净亏 -2.3%（排除）**；建议加价 +30%~+40%，瞄准中高单价作物（溪叶菜/琥珀豆/铃花莓/蜜穗瓜）。
- 既有复用面（已核实存在）：`RecipeDefinition.swift`（id/nameKey/inputs/outputs/placedObjectID/requiredUnlockID）、`CraftingService.craft`（数据驱动、失败不扣料、原子性）、`PlacementService`（预览/冲突/失败不扣料）、`EconomyCatalog`（listPrice/可售判定）、`ContentCatalog.vs0Recipes`。
- 基线计数：既有全部用例（当前权威 xcresult ≥228）不得回归；N-001 零位图红线延续——本任务**不得新增位图/音频文件**。

## 3. 必须做（In scope）

1. **加工站放置物**（数据驱动）：稳定 ID（建议 `brookseed.placeable.cooking_hearth`，命名待 🎭 content 审核）、配方解锁、可放置于农场、复用 `PlacementService`；视觉用程序化占位（几何色块 + 中文标签，与 N-001 同风格），**不触碰 `Assets/`**。
2. **加工配方**（数据驱动）：至少 3 条，覆盖中高单价作物（建议溪叶菜→蜜烤溪叶菜、琥珀豆→蜜烤琥珀豆、蜜穗瓜→蜜烤蜜穗瓜；可含铃花莓）；**排除雾萝卜**。成品定价 = 原料基础售价 × (1.30~1.40)，全部入数据文件。
3. **加工服务**：复用/扩展 `CraftingService.craft` 语义——原子、失败不扣料/不扣体力、成功扣料 1→成品 1（或按配方数量）、体力 −2/次；**即时完成，零存档 schema 增量**（不新增加工队列/燃料，不需要 schema 迁移）。
4. **交互与反馈**：对准已放置加工站按交互键打开加工面板（复用制作面板样式，过滤加工配方）；成功 ✅ + 中文反馈，失败 ❌ + 简短原因；键鼠/手柄可达（FR-010 不回归）。
5. **经济落账**：加工成品为可售物品（listPrice 可售），投入出售箱→日结→到账一次；原料/成品总量守恒，无复制/丢失/重复结算。
6. **自动化测试**：XCTest 覆盖——加工成功账目一致、失败不扣料/不扣体力、放置失败不扣料、成品出售日结不重复到账、存读往返一致；既有用例 0 回归。

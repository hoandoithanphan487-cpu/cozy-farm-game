## 参考设备与可用方式

| 必填项 | Product Owner 提供/确认 |
|---|---|
| 设备型号 | MacBook Air（13 英寸，M4，2025 年）；Model Identifier `Mac16,12`、Model Number `MW0W3CH/A` |
| 芯片（完整型号） | Apple M4（10 核 CPU：4 性能核、6 能效核；8 核 GPU） |
| 内存 | 16 GB |
| macOS 版本 | 26.5.2 |
| 存储类型 | 内置 256 GB SSD |
| 显示器刷新率 | 60 Hz |
| 可用方式 | 本机实机（当前工作区主机；Product Owner 指定为实际测试设备） |
| 若为替代设备 | 仅在本机不可用时适用；记录完整规格、基准证据来源、采集日期、工具/版本、原始结果和质量批准 |

设备档案采集来源：2026-07-30 的本机 `system_profiler` 输出及 Product Owner 对内置 256 GB SSD 和 60 Hz 的确认。该设备是 PRD-NFR-001/TDD 第 14 节的性能基线，可用于功能、离线启动、烟雾和性能证据。

替代设备必须具有可审计、可复跑的性能比较：记录工作负载、工具和版本、系统版本、原始输出、采集日期与来源链接/文件校验值，并证明替代设备不高于参考设备的性能。证据不足时，🛡️ quality 必须判定 `BLOCKED`。

## 每次运行的固定记录

每次性能、加载、存档、输入、离线启动或烟雾运行均创建一份 `manifest.md`，不得跨构建合并记录。至少包含：

| 分类 | 必记字段 |
|---|---|
| 身份 | 候选构建版本、构建 ID、SHA-256、测试日期/时区、测试人员、测试平台 |
| 设备 | 型号、CPU、GPU、内存、存储类型、操作系统及精确版本、分辨率、刷新率 |
| 构建 | Godot 4.7.1 标准版、发布/开发构建类型、arm64 架构、2D Compatibility 渲染器 |
| 环境 | 可用方式、供电/节能模式、后台程序/异常、网络接口断开方式与确认结果 |
| 结果 | 夹具 ID、步骤、通过/失败、原始数据、汇总统计、日志/截图/存档/视频相对路径、缺陷 ID（如有） |

## 验收矩阵与通过标准

所有性能路线固定为：1920×1080、macOS arm64 发布构建、Compatibility 渲染器；先预热 60 秒，再运行 10 分钟压力路线。完整切片路线覆盖两张地图、7 名 NPC、雨天、最大切片农田、制作放置、社交事件及一次存档。尚未实施的夹具必须标记为“未运行”。

| 夹具 / 验收项 | 操作与样本 | 通过标准 | 最晚阶段 |
|---|---|---|---|
| 帧时间 | 预热 60 秒后 10 分钟；保存每帧原始采样和 P95/P99 | P95 ≤16.67 ms；P99 ≤25 ms；加载遮罩外无 >50 ms 单帧 | M4 |
| 加载 | 连续切图 10 次；保存每次计时和 P95 | P95 <3 秒 | M4 |
| 自动存档 | 自动存档 20 次；保存每次耗时和 P95 | P95 <500 ms，并有保存中反馈 | M4 |
| 内存 | 发布构建记录进程峰值；开发构建同时保留性能分析器峰值 | 目标 <1 GB；两种构建类型不得混称 | M4 |
| 键鼠 | 新游戏及 VS-0 路径操作、失焦/恢复后的关键操作 | 所有必需操作可完成 | VS-0 / M4 |
| 手柄 | 已批准的兼容手柄执行移动、交互、菜单/确认与保存读取 | 所有必需操作可完成；记录型号与连接方式 | VS-0 / M4 |
| 保存读取 | 新游戏、手动保存、自动存档、退出/启动、读取；保留样本 | 状态可读，待结算出售不重复结算 | VS-0 / M4 |
| 离线启动与烟雾 | 断开所有可路由网络接口后安装、启动、新游戏、输入、保存读取和 VS-0 路径 | 全部完成且证据齐备 | M4 |

## 断网操作与证据保全

1. 关闭 Wi-Fi，拔除/禁用有线网络和其他可路由网络接口；关闭前记录接口状态。
2. 记录所有接口不可联网的时间戳证据。
3. 从本地安装包完成安装（如该候选需安装），启动游戏，创建新游戏，执行键鼠或手柄输入、保存与读取，并在适用阶段执行 VS-0 烟雾路径。
4. 保存启动日志、网络状态证据、截图/短视频、存档样本、构建版本与校验值；仅在证据收集完成后恢复网络。

统一证据根目录为 `artifacts/acceptance/<candidate-build-id>/macos-arm64/<run-id>/`；每次运行至少保留：

```text
manifest.md
device-profile.json
build/identity.txt
offline/network-before.*
offline/network-disabled.*
logs/
metrics/
screenshots-or-video/
saves/
```

## BLOCKED 判定与质量门禁

🛡️ quality 必须将受影响任务判为 `BLOCKED`，如果发生任一情况：

- 缺少完整的参考设备档案、获批准的替代设备档案或明确可用方式；
- 替代设备没有可审计的性能比较证据；
- 无法获得参考实机执行最终验收；
- 测试记录缺少 CPU、GPU、内存、操作系统、Godot 版本、构建类型、分辨率或刷新率；
- 断网、构建身份、日志/截图/存档样本、原始指标或失败步骤无法追溯；
- 以计划文本或编辑器可启动替代目标构建的验收结果。

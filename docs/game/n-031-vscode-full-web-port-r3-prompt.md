## 5. Phase A：Web 架构重建

保留现有 Vinext/Vite/Sites 工程、包管理器、锁文件和 `.openai/hosting.json`，但重建游戏运行层。

### 强制架构

1. 世界画面必须由一个真实 Canvas/WebGL 2D 游戏运行层绘制。
2. 推荐在 React/Vinext 客户端壳内使用 Phaser 3；如果现有兼容栈更适合 PixiJS，也可选择 PixiJS，但必须在 `architecture.md` 说明理由并证明支持相机、分层、碰撞、动画、输入和资源生命周期。
3. 禁止继续用 CSS Grid、成百上千个 `<div>`、emoji、渐变色块或通用卡片拼接地图和角色。
4. React 只负责浏览器壳、可访问的菜单/设置/导入导出和必要覆盖层；地图、角色、物体、粒子、动画、相机和世界交互由游戏运行层负责。
5. 领域状态与渲染分离：
   - `domain/`：纯 TypeScript 状态、服务、事务和规则；
   - `content/`：稳定 ID 与数据定义；
   - `runtime/`：场景、相机、图层、输入、动画、音频；
   - `persistence/`：版本化存档、校验、迁移、备份与导入导出；
   - `ui/`：HUD、对话、菜单、设置和无障碍桥接。
6. 运行时不得解析 Markdown。对白、地图、内容和规则必须在构建期转成经过校验的 JSON/TypeScript 数据。
7. 建立 `source-lock.json` 或等价文件，记录本次移植所读取的权威 Swift/内容/资产哈希。权威源以后发生变化时，漂移检查必须失败并指出需重新迁移的条目，不能静默失配。
8. 不引入后端。全部游戏逻辑在浏览器本地执行；持久化使用 IndexedDB，必要时只用 localStorage 保存非常小的设置或迁移标记。

### 依赖原则

- 只添加完成 2D 游戏运行必需的开源前端依赖。
- 添加依赖前检查现有 `package.json` 和锁文件；更新锁文件并记录许可证与用途。
- 不引入与现有功能重叠的大型 UI/状态库。
- 不使用远程 CDN 脚本、运行时外链字体或需要密钥的服务。

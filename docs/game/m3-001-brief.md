# Studio task: M3-001 两张地图与七名角色基础内容

**Status:** accepted / APPROVED（2026-08-18；🎭 content 与 🛡️ quality 双门禁通过）

## 1. 玩家结果

玩家可以从现有农场进入原创的“溪岸集市”小地图，再返回农场；两张地图均有清晰名称、边界、出口和占位地标。溪岸集市中的三名职能角色与四名邻居全部可见、可接近、可逐句交谈。内容使用稳定 ID 和数据定义；保存、退出、重启后仍位于保存时地图。目标是先交付可玩、可读、可验证的占位版本，不做美术、日程或社交系统打磨。

## 2. 责任与顺序

1. **Cursor（唯一实现者）**：扩展 Swift 内容模型、两张地图、七名角色、基础对白、最小地图切换、存档迁移与聚焦测试；只做一次自测。
2. **Xcode（唯一人工运行入口）**：Build/Test，然后人工走一遍“农场→集市→依次交谈→保存→退出→重启→返回农场”；不改代码。
3. **Hermes（只读质量负责人）**：检查原创性、引用完整性、可达性、文件边界与 Xcode 证据，返回 `APPROVED | REVISE | BLOCKED`；不得修改源码或台账。
4. **Codex**：只在 Hermes `APPROVED` 且 Xcode 证据完整后更新台账。Cursor、Xcode、Hermes 均不得自行把 M3-001 标为 accepted。

## 3. In scope

- 数据驱动的 `MapDefinition`、`MapExitDefinition`、`NpcDefinition` 与基础对话池；稳定 ID 不使用显示文本作为逻辑键。
- 两张原创小地图：现有农场/农舍区域和新增溪岸集市；使用清晰占位色块、标签、碰撞、出生点与双向出口。
- 三名职能角色：水工学徒、种源管理员、溪岸巡护员。水工学徒保留既有稳定 ID；另外两名使用新稳定 ID。
- 四名邻居：沿用 PRD 当前角色定位，但 Cursor 必须给出不与知名作品混淆的最终原创姓名；每名 4–6 句基础对白。
- 三名职能角色各 3–5 句基础对白；只介绍职责、地点和当前社区，不接任务、不改信任、不发奖励。
- 所有七名角色在溪岸集市可见、可接近、可重复交谈；对白期间时钟暂停，结束后恢复；重复交谈不得改变权威状态。
- 最小地图状态：`currentMapID` 进入 `GameState` 与存档；schema v3→v4 迁移默认落在农场；非法地图 ID 被校验拒绝。
- 内容校验与 XCTest：重复 ID、缺失地图/对白引用、越界出生点、出口引用错误、角色重叠或阻断出口必须失败；两张地图和七名角色数量、对话行数及往返存档必须通过。

## 5. 最小可观察验收

1. 新游戏保持 VS-0 已验收初始值和教学路径不回归。
2. 玩家可通过可见出口从农场进入溪岸集市，并从集市返回农场；无越界或软锁。
3. 集市明确显示三名职能角色和四名邻居；七人都能接近并完成基础交谈。
4. 每名邻居 4–6 句、每名职能角色 3–5 句原创基础对白；对白不承担任务、信任或事件逻辑。
5. 对话期间时间暂停，结束后恢复；重复交谈不发奖励、不推进隐藏状态。
6. 保存于溪岸集市后完全退出并重启读取，仍在溪岸集市且玩家位置合法；返回农场后仍可继续既有农耕/出售操作。
7. 内容定义均有稳定 ID；错误引用、越界、重叠和阻断出口由验证或测试明确拒绝。
8. 既有 XCTest 全绿，新测试覆盖地图往返、七名角色、对白范围、校验失败和 v3→v4 迁移。
9. 占位表现清楚可读，不依赖颜色作为唯一提示；不要求正式美术。
10. 未实现 M3-002/M3-003 功能，未复制任何受保护的名称、对白、地图布局、角色设计或视觉表达。

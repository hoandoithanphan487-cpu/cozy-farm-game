# IDEA-002 影响评估:像素美术资产管线

**想法 ID:** IDEA-002 | **捕获:** DEC-020(两拍走第二拍)| **评估日期:** 2026-08-19
**组织:** 🎬 director;五部门事实基于现有源码与文档证据
**状态结论:** **建议「暂缓为独立增量」** —— 与第一拍程序化升级互斥度低但依赖强(先有稳定的表现层接口),采纳条件为:先完成第一拍 + 风格试点验收 + 资产预算决策。

---

## 1. 想法还原

引入 AI 生成(ComfyUI/ChatGPT)原创像素贴图(角色/物品/地图),建立位图渲染管线(SKTexture + `filteringMode = .nearest` + 整数缩放),替换程序化占位表现;落实 PRD 7.1(24×24 地块、32×48 角色)与 NFR-007。

## 2. 跨部门事实(基于现有代码与文档证据)

### 现状基线(证据)

- 全仓**零位图纹理**:`imageNamed`/`SKTexture(image` 零命中;42 处渲染调用全部程序化(SKShapeNode/SKSpriteNode/SKLabelNode,集中于 `FarmScene.swift`)— 本机 A0-001 静态探针 P-1 结论。
- NFR-007 当前判定 PASS(无位图纹理即无非预期模糊);引入位图后须配置 `filteringMode = .nearest` 与整数缩放,否则违反 NFR-007(观察项 O-3)。
- PRD 7.1 定义:地块 24×24 像素、角色 32×48 像素、16:9 内部分辨率整数缩放;7.2 色彩(苔绿/雾蓝/湿土褐/木蜜/铜橙)。
- 渲染入口单一(`FarmScene.swift`),替换路径集中;内容引用(ContentID/ItemDefinition 等)不依赖渲染实现,位图替换对数据层透明。

### 🌱 design — 视觉目标与玩家体验

| 项 | 事实 |
|---|---|
| 视觉目标 | PRD 7.1「温暖手工像素」;程序化色块与正式像素的观感差距 = 本想法主要价值 |
| 风险 | 生成资产风格一致性难保证(同 Prompt 系列可能漂移);需要风格规范(调色板/轮廓/比例)先行 |
| 与第一拍关系 | 第一拍程序化升级(主题色/发型/表情/微动效)建立「角色辨识度」基础;像素替换在其上做资产化,而非从零 |

### 🎭 content — 原创性与审核

| 项 | 事实 |
|---|---|
| 原创性审核 | **主要成本**——AI 生成贴图可能含受保护表达(角色轮廓/图标撞已有作品);每件资产须审核:角色 7、作物 5、物品/配方产物、地图块、UI 图标(7.3 水工册页概念);审核工作量 ≈ 资产数量的 1–3 倍迭代 |
| 命名/风格 | 店名/角色名沿用现有原创体系(青砚/絮宁等);视觉词汇用 PRD 7.1「湿润石材、层叠木构、雾气植物、青铜水工件」 |
| 资产预算 | 需 PO 决策:先做试点子集(1 地图 + 3 角色 + 5 作物)还是全量;全量 ≈ 50–100 件贴图 + 动画帧 |

### 🧱 tech — 管线与性能

| 项 | 事实 |
|---|---|
| 管线 | 新增:资产导入(TextureAtlas/目录)、SKTexture 缓存、`filteringMode = .nearest`、整数缩放(PRD 7.1)、像素对齐;渲染层从 ShapeNode 迁移到 SKSpriteNode 有统一入口(FarmScene),但 42 处调用点需逐一改造 |
| 动画 | 播种/浇水/收获/拾取/修渠动作反馈(7.1)需帧动画;程序化动效可保留为过渡 |

| 存档/内容 | 数据层不变;ContentID/ItemDefinition 稳定 ID 与渲染解耦,替换无 schema 影响 |

## 3. 评估结论

**建议:暂缓为独立增量(第二拍),先完成第一拍。**

- 采纳条件(全部满足后再创建任务):① 第一拍程序化表现升级完成并验收;② 风格规范定稿(design);③ PO 批准试点资产预算;④ 原创性审核流程就绪。
- 若第一拍验收后观感已达标且预算不足 → 建议 `deferred`(程序化即最终形态,PRD 7.1 像素目标降级为历史参考,须 DEC 记录)。
- 若试点成功 → 扩量为全量管线任务,并同步落实 NFR-007 实测验收。

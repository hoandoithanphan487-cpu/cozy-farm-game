# Studio task: M3-002 水渠主任务与水脉复苏

**Status:** accepted / APPROVED（2026-08-18；🧱 tech 与 🛡️ quality 双门禁通过）  
**Role contract:** 专项负责人 🎮 gameplay；部门质量负责人 🧱 tech；咨询 🌱 design、🎭 content；下游独立复核 🛡️ quality。

## 1. 玩家结果

玩家在第 2 个脚本化游戏日可以从农场和溪岸集市的保底采集点取得足够材料，制作并合法放置一个水渠接片，获得一次性水脉复苏 `+12`；随后向水工学徒回报施工结果（不再消耗材料），获得一次性 `+8`。水脉达到 20 后，干涸水道切换为恢复状态，环境音、采集点和雨水桶配方同步解锁。整条主线不读取社区风评或信任门槛，保存、退出、重启后保持一致，重复操作不重复奖励。

## 2. 责任与交付顺序

1. **🎮 gameplay（唯一实现负责人）**：实现数据模型、领域事务、存档迁移、SpriteKit 反馈与聚焦测试；遵守现有 Swift 分层和稳定 ID。
2. **🧱 tech（部门质量负责人）**：检查事务边界、幂等、内容验证、存档兼容、失败回滚和测试证据，返回 `APPROVED | REVISE | BLOCKED`。
3. **🛡️ quality（独立复核）**：使用同一候选构建执行一次关键路径、跨进程存读和回归检查，返回明确质量门禁。
4. **🎬 director**：仅在 🧱 tech 与 🛡️ quality 均 `APPROVED` 后登记验收；任何实现者不得自行将 M3-002 标为 accepted。

## 3. In scope

- 数据驱动的保底采集节点：农场至少溪木×8、苔石×4、芦纤维×6；溪岸至少溪木×6、苔石×8、芦纤维×6。保底产出确定、一次性且可保存；内容验证证明只用保证节点即可覆盖水渠接片成本溪木×6、苔石×4。
- 主任务“让旧水渠再次流动”：接取、进行、可回报、完成四态；任务文本和目标使用稳定 ID；关键路径禁止 `min_standing` 或任何信任条件。
- 复用现有制作/放置事务制作水渠接片；非法位置、冲突、越界、阻断出口或材料不足时不扣料、不推进任务、不增加水脉值。
- `WatershedState`、一次性贡献定义与服务：`place_canal_segment = 12`、`deliver_canal_repair = 8`；贡献来源和前置条件必须匹配，重复贡献返回幂等成功且不重复发奖。
- 放置成功后开放水工学徒回报；回报不消耗额外物品。达到 20 后一次性切换修复地图变体、流水环境音层、新采集点和雨水桶配方。
- 水脉、任务、采集节点与解锁状态进入版本化存档；旧存档迁移到合法默认状态，跨进程读取不重复应用贡献或解锁。
- 最小 HUD/场景反馈和开发调试可见性；沿用原创占位表现，不要求正式美术或音频资产。

1. 新游戏与既有 M1/M2/M3-001 路径不回归；两张地图和七名角色仍可达。

3. 材料足够时可制作一个水渠接片；失败制作或失败放置不扣料、不生成对象、不改变任务或水脉。

7. 达到 20 后地图呈现恢复水道、环境音状态改变、新采集点可用、雨水桶配方解锁；重复载入不会重复创建或发奖，且反馈不只依赖颜色。

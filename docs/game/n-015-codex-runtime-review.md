## 3. 阻断视觉门禁的问题

### R1 默认玩家画面仍主动绘制调试/占位符

`FarmScene.swift` 的正常渲染路径仍创建深色阻挡格和文字“阻”，并继续绘制“石阶”、地标文字、“成熟”方框和缺图时的“采”。运行截图 01、03、04 均直接显示了这些元素。N-015 的核心目标是清除程序化占位主视觉，因此不能把它们解释为允许的 B4 说明标记。

验收：默认 HUD 模式下不得出现“阻”“石阶”“采”等单字/调试地标占位；碰撞边界应由环境、建筑 footprint 或可读的自然障碍表达。调试信息只能由显式 H 层开启。

### R2 角色缩放使用了地砖倍率，导致人物巨大

`SpriteSheetAnimator` 直接将 `cellSize / 24` 的地砖倍率同时乘到 32×48 角色帧。角色原生宽度已经大于 24 像素地砖，结果人物宽于一格、高达两格以上；实际截图中玩家和 NPC 大量覆盖作物、地标、彼此与 HUD。

验收：为角色建立独立的像素倍率/目标世界高度合同，在 960×640 与 1280×800 下保持脚点、碰撞格和遮挡关系可信；8 名角色不得互相堆叠或压住交互目标。

### R3 水体“全资产覆盖”代替了正确拓扑拼接

`WorldVisualCatalog` 在每张地图只布置两个水格；`waterBorder` 会为单格返回多个边与角，`FarmScene` 随后把全部 edge/corner sprite 叠到同一个格子。这个实现能让测试看见所有资源名，但截图中的水面成为突兀的蓝色块和重叠边角，不能代表完成的河道/水渠。

验收：每个水格根据邻接关系选择正确的基础 tile 或互不冲突的边角组合；用有方向、有入口/出口的连续水体构图覆盖两张地图，不得为了消费者计数把多张互斥 tile 叠在同一格。

### R4 地图仍是稀疏的平绿矩形，缺少完整构图

正式资产目前被零散地放进场景，但没有形成明确的道路、水岸、农田、建筑、树石边界、NPC 活动区和视觉焦点。市场截图同样以空旷底色、阻挡方块和巨大 NPC 为主。

验收：先产出两图的像素构图/占用草图，再实现连续地形层、边界层、道路/水体层、建筑层、角色与前景遮挡层；截图要能在不看文字标签的情况下区分农场与集市，并读出主要通路。

### R5 默认 HUD 与世界对象互相遮挡

底部目标、提示与 toast 区域会覆盖作物、玩家和出口文字；右上建筑展示卡长期占用大块地图。当前只是把调试大面板移到 H 层，并没有完成世界安全区、提示优先级和临近建筑展示行为。

验收：HUD 需要明确安全区；临时提示自动消退且不与目标/操作提示堆叠；建筑卡仅在临近交互或明确打开时出现，并支持收起；960×640 是硬验收视口。

### R6 “视觉证据”是合成的静态测试，不是真实游玩链路

`N015RuntimeVisualEvidenceTests` 直接构造 `GameState`，通过 DEBUG 注入场景后在离屏 `SKView` 截图，再与 SwiftUI overlay 合成。它能做回归快照，但没有证明从真实 App 启动、键鼠/手柄移动、三动作、FX、切图、建筑触发和 HUD 状态转换的端到端体验。

验收：保留现有快照测试，新增真实 App 窗口录屏或连续帧证据；至少覆盖新档进入农场、四向移动、耕地/浇水/收获、一次 FX、切到集市、触发一栋建筑展示、打开/关闭 H 层。证据必须来自同一构建。

## 4. 建议返工顺序

1. R5.1：先修角色独立缩放、NPC 站位和 HUD 安全区，立即消除最大面积的视觉冲突。
2. R5.2：移除默认占位文字与几何标记；同时把碰撞表达迁移到正式环境层。
3. R5.3：重做两图视觉布局与水体拓扑；测试改为验证语义正确性，不只验证所有资源都曾出现。
4. B4：Product Owner 批准地图重排后，接入五建筑六层像素层、入口、碰撞和遮挡。
5. B5：用真实 App 游玩链路重录视觉证据，再做 🧱 tech → ✨ ux / 🎭 content → 🛡️ quality 的顺序复闸。

推荐 Product Owner 选择“地图重排”。纯视觉缩小不能同时解决建筑比例、入口、碰撞、遮挡、现有“阻”标记和两图空旷构图问题。该推荐不等于已获得地图拓扑修改授权。

## 5. 关闭条件

- 102 个现有消费者保持可解析，30 个 B4 资产在 PO 决策后形成真实玩家路径。
- 默认画面不再出现程序化占位主视觉；调试内容只存在于显式 H 层。
- 两种验收分辨率下角色、建筑、作物、水体与 HUD 无不可接受的重叠或比例错误。
- 水体、路径和建筑按地图语义正确落位，而不是为了计数堆叠互斥资产。
- 全量 XCTest、资源验证、性能、真实窗口截图/录屏与存读/输入回归全部来自同一候选构建。
- 独立部门门禁返回 `APPROVED`，随后才可请求 Product Owner 最终视觉验收；N-016 在 N-015 `accepted / APPROVED` 前仍不启动。
